# POS Dual Report Import

## วัตถุประสงค์

ระบบรับรายงานจาก POS สองประเภทในช่วงวันที่เดียวกัน แต่เก็บและประมวลผลแยกกัน เพื่อไม่ให้ยอดขายตามบิลปะปนกับจำนวนขายตามเมนู

## ไฟล์ที่ 1: รายงานการขายตามรายละเอียดบิล

ใช้สำหรับเชื่อมยอดขายลูกค้ากับรอบเปิดโต๊ะของ Sales

คอลัมน์ขั้นต่ำที่ระบบต้องอ่านได้:

- เลขบิล / เลขที่บิล / Receipt No.
- วันที่ขาย หรือวันเวลาขาย
- ยอดขายสุทธิ
- หมายเลขโต๊ะ (ถ้ามี)

ระบบรวมแถวที่มีเลขบิลเดียวกันเป็นหนึ่งบิล แล้วนำเลขบิลไปเทียบกับเลขใบเสร็จที่บันทึกตอนปิดโต๊ะ หากพบตรงกันจะบันทึกยอดขายที่จับคู่ไว้ในรอบโต๊ะ Sales

## ไฟล์ที่ 2: รายงานการขายตามเมนู

ใช้กับขั้นตอน Mapping, Sort, ค่าดื่ม และค่าคอม

คอลัมน์ขั้นต่ำที่ระบบต้องอ่านได้:

- ชื่อสินค้า/เมนู
- จำนวนขาย
- ยอดขาย
- กลุ่มหรือหมวดหมู่ (ถ้ามี)

ชื่อเมนูในกลุ่ม PR/Sales ยังคงหมายถึงจำนวนดื่มของพนักงาน ไม่ใช่ยอดเชียร์ลูกค้า

## ลำดับการทำงาน

1. ระบุชื่อ Report รายละเอียด และช่วงวันที่
2. เลือกไฟล์รายละเอียดบิลและไฟล์ยอดขายตามเมนู
3. ระบบตรวจชนิดข้อมูลของแต่ละไฟล์ก่อนบันทึก
4. Process ไฟล์รายละเอียดบิลเพื่อจับคู่เลขใบเสร็จกับรอบโต๊ะ Sales
5. Process ไฟล์เมนูเพื่อเข้า Mapping/Sort และคำนวณค่าดื่ม/ค่าคอม
6. ตรวจผลที่หน้า Report

## การล้าง Report

การล้างเป็น Soft Clear และมี Audit Log

- ล้างรายงานรายละเอียดบิล: ยกเลิก batch และคืนสถานะรอบโต๊ะที่เคยจับคู่กลับเป็นรอตรวจ
- ล้างรายงานเมนู: ทำได้เมื่อยังไม่มีรอบจ่ายเงินที่ล็อกข้อมูล
- ไม่มีการลบประวัติ Audit

## ขอบเขตปัจจุบัน

ยอดบิลที่จับคู่จะแสดงเป็นข้อมูลประกอบของ Sales ก่อน ระบบยังไม่นำยอดดังกล่าวไปคิดค่าคอมอัตโนมัติ จนกว่าจะกำหนดสูตรหรืออัตราค่าคอมจากยอดเชียร์อย่างชัดเจน
